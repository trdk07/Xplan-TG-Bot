# 會員 V2 實作驗收紀錄（2026-10-28）

交易量門檻為 200,000 USDT，歷史累積入金門檻為 100 USDT。這份紀錄區分離線功能驗證與正式能力啟用。

## 程式功能驗證

| 專案 | 最後驗證結果 |
| --- | --- |
| TG／管理後台 | `npm test` 327 項通過；`npm run typecheck`、`npm run cf:build` 通過 |
| Discord Worker | 171 項測試、型別檢查、Wrangler dry-run、V1／V2 workerd 模擬通過 |
| 官網 | 33 項測試、API 型別檢查、建置通過 |
| 捉妖小道 | 1488 項通過，4 項既有條件式測試略過；型別、工作區與 V2 前端建置、模擬 RPC 通過 |

核心覆蓋精確小數邊界、完整台北日、入金去重／下限、故障保留、付費優先／到期轉級、租約過期、重複帳號、人工覆核、提醒及未知發送結果。整合審查提出的五項問題已加入迴歸案例並修正：

- 所有應用程式內的資格、付款、停用、補件與到期處理共用同一會員租約；權威寫入前核對租約。
- 模糊的舊付費狀態不能藉由歷史付款日與未來截止日升級；新付款核准獨立建立可信付費期間。
- 每次通知及付款截止處理重新讀取最新週期，防止並行續費被舊資料覆蓋。
- 直接 TG 重查也須完整查核 Notion 的交易所＋UID 唯一性；D1 第一個保留成功不等於身分唯一。
- 在 Notion 狀態更新前持久保存升降級通知意圖；每日工作恢復處理，避免後台重查或中斷造成遺漏。到期與交易量通知的重疊及中斷恢復亦有測試。

另外確認 API 故障在保留成功證據時，仍回報既有管理員告警流程；刻意關閉／尚未驗證的能力不當作零交易量。

後台以真實 React 元件及合成會員資料檢查桌面／390px 手機列表與詳細頁；官網、捉妖小道以攔截的合成 API 回應檢查表單。這些是本機 UI 與模擬測試，未執行真實會員登入、付款、TG 入群或 DC 角色修改。
